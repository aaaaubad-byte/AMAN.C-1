# خريطة نقل AMAN.C إلى AMAN.C-1

## الحالة
لم يبدأ نقل ملفات التطبيق بعد. هذه الخريطة تسجل ما يلزم فحصه قبل النقل.

## مناطق المصدر المعروفة
| المنطقة | المصدر المعروف | الإجراء المبدئي |
|---|---|---|
| تطبيق العميل | client/app.js وملفات HTML/CSS/PWA المرتبطة | جرد الاعتماديات ثم نقل الشاشة وسلوكها دون إعادة تصميم |
| تطبيق الإدارة | admin/app.js وملفات المراحل الإضافية | تتبع التحميل والترتيب والوظائف قبل الدمج |
| الخدمات | services/runtime.js وsupabase-adapter.js وsupabase-config.js | مطابقة العقود مع الدوال الحية قبل اعتمادها |
| المحاكاة | simulation/simulation-adapter.js | عزلها بوضوح وعدم خلطها بالتشغيل الحقيقي |
| الأنماط | styles/app.css وvisual-v6.css وملفات الأنماط المساعدة | فحص ترتيب التحميل والتكرار والاعتماديات |
| PWA | ملفات manifest وservice worker لكل تطبيق | الحفاظ على الفصل ومراجعة التخزين المؤقت والمسارات |
| قاعدة البيانات | ملفات SQL المحلية مقابل ستة ترحيلات حية | اعتماد المخطط الحي مرجعاً، ومراجعة الفروقات |
| الاختبارات | اختبارات المصدر وإعدادات CI | تقييم التغطية وإعادة إنشاء اختبارات موثوقة |

## تغييرات المصدر التي تحتاج مراجعة خاصة
- PR #13 متباعد تاريخياً عن main؛ يجب مراجعة أي سلوك فريد فيه قبل إسقاطه.
- PR #32 يحتاج فحص ملفاته وتحديد ما إذا كانت وظيفته موجودة بالفعل في main.
- يوجد مساران ظاهريان لاعتماد/رفض بعض الطلبات؛ يجب إثبات المسار الفعلي قبل إزالة أي منهما.
- بعض الملفات تُحمّل ديناميكياً؛ لا يجوز الحكم على عدم استخدامها من نتائج البحث الساكن وحدها.
- توجد فروقات بين SQL محلي قديم والقاعدة الحية، بما فيها أعمدة ودوال تشغيلية؛ لا تنقل SQL القديم باعتباره الحالة الحالية.
