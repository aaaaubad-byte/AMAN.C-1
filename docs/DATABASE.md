# مرجع قاعدة البيانات

## القرار
يستمر المشروع على قاعدة بيانات AMAN الحالية نفسها. لا تنشأ قاعدة بديلة ضمن التأسيس، ولا يتم تغيير القاعدة الحية دون موافقة صريحة.

## ما تم التحقق منه مبدئياً
- مشروع Supabase متصل، ويحتوي على 22 جدولاً عاماً.
- جميع الجداول الـ22 مفعّل عليها RLS.
- توجد 48 دالة بصلاحية SECURITY DEFINER، و46 منها قابلة للتنفيذ من authenticated وفق الفحص الأولي.
- قائمة الترحيلات الحية تتضمن ستة ترحيلات حتى 2026-11-03.
- توجد اختلافات بين بعض ملفات SQL القديمة في المصدر وبين بنية القاعدة الحية؛ لذلك لا يجوز اعتبار SQL القديم وصفاً كاملاً للقاعدة.

## الجداول المرصودة
app_content, audit_log, companies, company_prefixes, company_task_settings, notification_broadcasts, notifications, number_alerts, number_links, numbers, operation_requests, payment_methods, profile_status_history, profiles, protection_events, protection_packages, protections, reactivation_settings, rejection_reasons, report_actions, reports, tasks.

## قواعد التعامل
1. قراءة وفهم المخطط الفعلي والدوال والسياسات والاعتماديات قبل اقتراح أي تعديل.
2. مطابقة كل استدعاء من التطبيق مع الدالة والجداول الفعلية.
3. عدم تعديل ترحيل مطبق؛ أضف ترحيلاً جديداً فقط عند الحاجة.
4. قبل أي تطبيق حي: مراجعة التغيير والبيانات المتأثرة والصلاحيات وخطة الاستعادة.
5. لا تنفيذ حي دون موافقة صريحة مستقلة.
6. لا حفظ مفاتيح خاصة أو service role أو أسرار في Git.

## ملاحظات فحص تحتاج متابعة
- 34 مفتاحاً أجنبياً دون فهرسة بحسب مستشار قاعدة البيانات.
- أربعة فهارس ظهرت كغير مستخدمة.
- توجد دوال ذات صلاحية مرتفعة تحتاج مراجعة منطق التفويض والاستدعاءات.
- معظم الجداول لا تملك سياسات مباشرة ظاهرة، وقد يكون الوصول مقصوداً عبر RPC؛ لا تصنف ذلك خللاً قبل مراجعة المسارات الفعلية.
- حماية كلمات المرور المسربة غير مفعلة وفق الفحص الأولي؛ يراجع أثر تفعيلها قبل اتخاذ قرار.

هذه ملاحظات تدقيق وليست تغييرات منفذة أو أحكاماً نهائية.
