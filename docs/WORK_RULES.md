# قواعد العمل والتنفيذ

1. اقرأ `README.md` و`docs/RESUME.md` و`docs/DECISIONS.md` و`docs/PRODUCT.md` و`docs/ARCHITECTURE.md` و`docs/DATABASE.md` قبل أي تغيير.
2. اعمل على فرع feature معتمد؛ لا تعدّل `main` أو `develop` مباشرة.
3. لا تعدّل مستودع AMAN.C الأصلي.
4. لا تغيّر قواعد المنتج أو تدفق العمليات أو نصوص الواجهات أو التصميم أثناء إعادة التنظيم.
5. لا تضف إطار عمل أو اعتماداً جديداً بلا حاجة تقنية مثبتة.
6. لا تدمج ملفين بسبب تشابه الاسم فقط؛ تتبع الاستدعاءات والسلوك والاختبارات أولاً.
7. لا تحذف مسار الاعتماد/الرفض المكرر حتى تنجح الاختبارات المرتبطة به؛ هذا شرط صريح من المالك.
8. لا تضف أسراراً أو مفاتيح خاصة أو بيانات حقيقية إلى Git.
9. المحاكاة محلية فقط، ويحقنها `scripts/local-preview.mjs`؛ لا تضفها إلى صفحات الإنتاج.
10. استخدم قاعدة Supabase الحالية نفسها؛ لا تنشئ قاعدة بديلة.
11. لا تعدّل مخطط القاعدة الحية ولا تطبق ترحيلاً دون مراجعة الأثر ونسخة قابلة للاستعادة وخطة استعادة وموافقة صريحة.
12. لا تنقل أو تطبق الترحيل القديم `20261101000100_initial_schema.sql` لأنه لا يطابق القاعدة الحية.
13. لا تضف إعداد نشر ولا تنفذ نشراً أثناء التطوير. النشر قرار مستقل يحتاج موافقة صريحة.
14. بعد كل دفعة حدّث `docs/RESUME.md` و`docs/MIGRATION_MAP.md` و`docs/DECISIONS.md` عند الحاجة، وسجل commit.
15. لا تدّع نجاح اختبار أو فحص متصفح إلا بنتيجة فعلية. عند الفشل أصلح السبب ولا تضعف الاختبار.
16. افحص مراجع HTML وCSS وJavaScript وPWA والاختبارات والسكريبتات والتوثيق قبل حذف أي مسار.
17. عند نهاية الحصة حدّث نقطة الاستئناف بآخر commit مؤكد والخطوة التالية المحددة.
